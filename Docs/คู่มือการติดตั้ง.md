## เริ่มเร็ว — 8 ขั้น จบใน 20 นาที

ถ้าเคยติดตั้งมาแล้วครั้งหนึ่ง ทำตามนี้พอ ไม่ต้องอ่านทั้งไฟล์
**แต่ละขั้นทำเสร็จแล้วสั่ง `npm run setup` ได้ตลอด มันจะบอกเองว่าเหลืออะไร**

| # | ทำอะไร | ที่ไหน |
|---|---|---|
| 1 | `git clone` โค้ดมาเป็นโปรเจกต์ใหม่ | เครื่องตัวเอง |
| 2 | สร้างโปรเจกต์ Supabase เลือก Region สิงคโปร์ | supabase.com |
| 3 | วาง `supabase/schema.sql` ทั้งไฟล์แล้ว Run · **ดูตารางสรุปให้ขึ้น `ผ่าน` ครบทุกแถว** | SQL Editor |
| 4 | Add user + **ติ๊ก `Auto Confirm User`** | Authentication > Users |
| 5 | คัดลอก Project URL และ anon public key | Project Settings > API |
| 6 | `npm run setup -- --init` แล้วใส่ค่าสองตัวลง `.env.local` · สั่ง `npm run setup` อีกรอบให้ขึ้นว่าพร้อม | เครื่องตัวเอง |
| 7 | push ขึ้น GitHub แล้วสร้างโปรเจกต์ใน Vercel · ใส่ค่าสองตัวเดิม ติ๊กครบ 3 environment | github.com + vercel.com |
| 8 | **Redeploy หนึ่งครั้ง** แล้วเปิดเว็บล็อกอิน | Vercel > Deployments |

เสร็จแล้วไปตั้งค่าเริ่มต้นในโปรแกรมต่อ ตามชีต 4 ของ
[Docs/เช็คลิสต์การติดตั้ง.xlsx](Docs/%E0%B9%80%E0%B8%8A%E0%B9%87%E0%B8%84%E0%B8%A5%E0%B8%B4%E0%B8%AA%E0%B8%95%E0%B9%8C%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%95%E0%B8%B4%E0%B8%94%E0%B8%95%E0%B8%B1%E0%B9%89%E0%B8%87.xlsx)

### คำสั่งเดียวที่ควรจำ

```
npm run setup
```

ตรวจให้ทีละข้อว่าติดตั้งถึงไหนแล้ว แล้วบอกเป็นข้อ ๆ ว่าเหลืออะไรต้องทำ

## ภาพรวม — ระบบประกอบด้วยอะไร และติดตั้งเรียงยังไง

### ระบบมีสามส่วน ไม่ได้อยู่ที่เดียวกัน

```
  ผู้ใช้ (เบราว์เซอร์)
        |
        |  เปิดเว็บ
        v
  Vercel .............. ที่รันเว็บ  (เอาโค้ดมาจาก GitHub เอง ทุกครั้งที่ push)
        |
        |  ขอข้อมูลและล็อกอิน  (ใช้ Project URL + anon key)
        v
  Supabase ............ ฐานข้อมูล + ระบบล็อกอิน  (ข้อมูลจริงอยู่ที่นี่ที่เดียว)
```

**ข้อที่ต้องเข้าใจ** โค้ดอยู่ที่ Vercel แต่ข้อมูลอยู่ที่ Supabase
deploy ใหม่กี่ครั้งข้อมูลก็ไม่หาย และลบโปรเจกต์ Vercel ทิ้งข้อมูลก็ยังอยู่
กลับกัน ลบโปรเจกต์ Supabase เมื่อไร ข้อมูลหายทั้งหมดทันที

### ลำดับการติดตั้ง และเหตุผลที่ต้องเรียงแบบนี้

```
  [1] โค้ด
       |  git clone มาเป็นโปรเจกต์ใหม่
       v
  [2] Supabase                      <-- ต้องทำก่อน เพราะขั้นถัดไปต้องใช้ค่าจากที่นี่
       |  สร้างโปรเจกต์
       |  รัน schema.sql  ->  ได้ตาราง 44 ตาราง
       |  สร้างผู้ใช้คนแรก (ติ๊ก Auto Confirm User)
       |
       |  ได้ค่าสองตัวมา:   Project URL   และ   anon public key
       v
  [3] GitHub
       |  push โค้ดขึ้น repo
       v
  [4] Vercel
       |  ใส่ค่าสองตัวที่ได้จากขั้น [2]
       |  Redeploy หนึ่งครั้ง            <-- ไม่ทำ ค่าใหม่จะไม่มีผล
       v
  [5] เปิดเว็บ ล็อกอิน แล้วตั้งค่าเริ่มต้นในโปรแกรม
```

คนส่วนใหญ่เผลอทำ Vercel ก่อน Supabase แล้วติดตรงที่ไม่มีค่าจะใส่
ลำดับนี้จึงไม่ได้เรียงตามความคุ้นเคย แต่เรียงตามว่าอะไรต้องใช้ผลของอะไร

### ค่าสองตัวไปไหนบ้าง

```
  Supabase  >  Project Settings  >  API
        |
        |  คัดลอกสองค่า: Project URL และ anon public key
        |
        +---->  .env.local                        ใช้ตอนรันในเครื่อง (npm run dev)
        |
        +---->  Vercel > Environment Variables    ใช้ตอนรันบนเว็บจริง
                     |
                     |  ต้อง Redeploy หนึ่งครั้ง
                     v
               ค่าถูกฝังลงไฟล์ตอน build  ->  หน้าเว็บถึงจะเห็นค่า
```

**ค่าเดียวกันต้องใส่สองที่** ใส่ที่เครื่องอย่างเดียว เว็บจริงจะยังล็อกอินไม่ได้
และ `npm run setup` ตรวจได้แค่ฝั่งเครื่อง ตรวจฝั่ง Vercel ให้ไม่ได้

## ขั้นที่ 1 — วางโครงโฟลเดอร์

### ทางที่ 1: คัดลอกจากโปรเจกต์เดิม (แนะนำ)

```
git clone <ที่อยู่ repo เดิม> ชื่อโปรเจกต์ใหม่
cd ชื่อโปรเจกต์ใหม่
```

### ทางที่ 2: สร้างใหม่ทั้งหมด

โครงที่ต้องมี — ชื่อโฟลเดอร์ต้องตรงตามนี้ เพราะ Next.js หาไฟล์จากชื่อ:

```
ชื่อโปรเจกต์/
├─ app/                  หน้าเว็บและ API (Next.js App Router)
│  ├─ layout.js          โครงร่างหน้าเว็บ
│  ├─ page.js            หน้าแรก
│  ├─ globals.css        สไตล์ทั้งระบบ (ไฟล์เดียว)
│  └─ api/               Route Handler ที่รันฝั่งเซิร์ฟเวอร์
├─ components/           ส่วนประกอบหน้าจอ
│  └─ views/             หนึ่งไฟล์ต่อหนึ่งหน้าจอ
├─ lib/                  ตรรกะล้วน ไม่มี JSX — ทดสอบใน Node ได้ตรง ๆ
├─ public/               ไฟล์ที่เสิร์ฟตรง (โลโก้ ไอคอน manifest)
├─ supabase/
│  └─ schema.sql         สร้างฐานข้อมูลทั้งหมดจากไฟล์เดียว
├─ tools/                สคริปต์ช่วยงาน (ตัวตรวจ ตัวสร้างเอกสาร)
├─ Docs/                 เอกสารโครงการ
├─ package.json
├─ next.config.mjs
├─ jsconfig.json         ทำให้ import แบบ @/lib/... ใช้ได้
└─ .env.local            ค่าลับ — ห้ามขึ้น git (อยู่ใน .gitignore แล้ว)
```

**สามโฟลเดอร์ที่ห้ามสลับกัน**

- `lib/` ต้องไม่มี JSX เลย เพราะไฟล์ในนี้ถูกทดสอบด้วย Node ตรง ๆ โดยไม่ผ่าน build
- `components/` เป็นหน้าจอ ห้ามใส่ตรรกะการคำนวณ เพราะทดสอบไม่ได้
- `app/api/` รันฝั่งเซิร์ฟเวอร์เท่านั้น กุญแจลับอยู่ที่นี่ได้ที่เดียว

### ไฟล์ตั้งค่าที่ต้องมี

`package.json` — ส่วนที่ขาดไม่ได้:

```json
{
  "name": "ofau",
  "private": true,
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "check": "node tools/check.mjs"
  },
  "dependencies": {
    "next": "^15.5.0",
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  },
  "engines": { "node": ">=18.18.0" }
}
```

`jsconfig.json` — ถ้าไม่มีไฟล์นี้ `import ... from "@/lib/db"` จะพังทุกไฟล์:

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./*"] }
  }
}
```

`.gitignore` — ต้องมีสามบรรทัดนี้เป็นอย่างน้อย:

```
node_modules
.next
.env*.local
```

> `.env.local` หลุดขึ้น git เมื่อไร กุญแจในนั้นถือว่ารั่วทันที
> ต่อให้ลบ commit ทีหลังก็ยังอยู่ในประวัติ ต้องไปสร้างกุญแจใหม่ที่ Supabase

## ขั้นที่ 2 — สร้างฐานข้อมูลใน Supabase

### 2.1 สร้างโปรเจกต์

1. เข้า [supabase.com](https://supabase.com) > **New project**
2. ตั้งชื่อ และ **ตั้งรหัสผ่านฐานข้อมูล** (เก็บไว้ ใช้ตอนต่อฐานข้อมูลตรง ๆ)
3. เลือก Region ให้ใกล้ผู้ใช้ — **Southeast Asia (Singapore)** สำหรับผู้ใช้ในไทย
   เลือกผิดภูมิภาคแล้วย้ายทีหลังไม่ได้ ต้องสร้างโปรเจกต์ใหม่
4. รอประมาณ 2 นาทีจนสถานะขึ้นว่าพร้อม

### 2.2 รัน schema.sql — ขั้นตอนเดียวจบ

1. เมนูซ้าย > **SQL Editor** > **New query**
2. เปิดไฟล์ `supabase/schema.sql` **คัดลอกทั้งไฟล์** วางลงไป
3. กด **Run**

ไฟล์เดียวนี้ทำให้ครบทุกอย่าง:

| ทำอะไร | ทำไมต้องมี |
|---|---|
| สร้างตารางทั้ง 44 ตาราง | ข้ามตารางที่มีอยู่แล้ว ไม่แตะข้อมูลเดิม |
| สร้างฟังก์ชันบันทึกเอกสารแบบ atomic | ขายหนึ่งครั้งเขียน 3 ตาราง สำเร็จหมดหรือไม่สำเร็จเลย |
| เพิ่มเลขลำดับแถว (row_order) ทุกตาราง | ใช้เรียงและอ้างอิง เพราะ id เป็นข้อความสุ่ม |
| GRANT สิทธิ์ระดับตารางให้ role authenticated | ไม่ผ่านด่านนี้จะได้ HTTP 403 ทุกคำขอ |
| **GRANT สิทธิ์ sequence** | ขาดแล้วบันทึกไม่ได้เลยทุกตาราง (ดูหัวข้อแก้ปัญหา) |
| เปิด RLS และสร้าง policy ครบทุกตาราง | กันไม่ให้คนที่ไม่ได้ล็อกอินอ่านหรือเขียน |
| ตั้งทะเบียนผู้ใช้และสิทธิรายคน | คนที่สมัครก่อนสุดได้เป็นแอดมินอัตโนมัติ |

**รันซ้ำกี่ครั้งก็ได้ ปลอดภัย ไม่ลบข้อมูลเดิม** — และต้องรันซ้ำทุกครั้งที่อัปเดตโปรแกรมเป็นรุ่นที่มีตารางใหม่

### 2.3 ตรวจผลลัพธ์ — ข้อนี้ห้ามข้าม

ท้ายผลลัพธ์จะมีตารางสรุป **ทุกแถวต้องขึ้นว่า `ผ่าน`**

ถ้าเจอแถวที่ไม่ผ่าน อ่านข้อความแล้วแก้ตามนี้:

| ข้อความ | สาเหตุและวิธีแก้ |
|---|---|
| ไม่ผ่าน — ไม่มีตาราง | รันไฟล์ไม่ครบ ให้คัดลอกทั้งไฟล์แล้วรันใหม่ |
| ไม่ผ่าน — GRANT ไม่ครบ | รันไฟล์ไม่จบ ดูว่ามี error สีแดงกลางทางหรือไม่ |
| ไม่ผ่าน — ไม่มี RLS policy | เหมือนข้างบน |
| ไม่ผ่าน — sequence ยังไม่ได้ GRANT | รันไฟล์ใหม่ทั้งไฟล์ ต้องรันส่วนท้ายให้ถึง |

### 2.4 สร้างผู้ใช้คนแรก

ระบบนี้**ไม่มีหน้าสมัครสมาชิก** โดยตั้งใจ ผู้ใช้ถูกสร้างจาก Dashboard เท่านั้น

1. เมนูซ้าย > **Authentication** > **Users** > **Add user**
2. กรอกอีเมลและรหัสผ่าน
3. **ติ๊ก `Auto Confirm User`** ← ข้อนี้สำคัญที่สุด

> ไม่ติ๊กข้อนี้ จะล็อกอินไม่ได้เลย และระบบจะขึ้นว่า
> *"อีเมลนี้ยังไม่ได้ยืนยัน"* ซึ่งเป็นสาเหตุที่พบบ่อยที่สุดของการล็อกอินไม่ได้
> แก้ย้อนหลังได้ที่ Users > กดที่ผู้ใช้ > Confirm email

คนที่ถูกสร้างก่อนสุดจะได้เป็น **แอดมิน** อัตโนมัติ (ตั้งสิทธิให้คนอื่นได้)

### 2.5 เอาค่าสองตัวมาใช้ต่อ

**Project Settings** > **API** แล้วคัดลอกสองค่านี้:

| ช่องใน Supabase | เอาไปใส่ชื่อ |
|---|---|
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` |
| Project API keys > **anon** `public` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |

> **อย่าหยิบ `service_role` มาใส่เป็น anon key เด็ดขาด**
> กุญแจนั้นข้ามทุกสิทธิ์ ฝังไว้ในหน้าเว็บเมื่อไร ใครเปิดหน้าเว็บก็ลบข้อมูลทั้งระบบได้
> anon key เปิดเผยได้ตามปกติ ความปลอดภัยมาจาก RLS policy ที่ schema.sql ตั้งไว้แล้ว

## ขั้นที่ 3 — ตั้งค่าและ deploy บน Vercel

### 3.1 เอาโค้ดขึ้น GitHub

```
git init
git add .
git commit -m "เริ่มโครงการ"
git branch -M main
git remote add origin <ที่อยู่ repo ของคุณ>
git push -u origin main
```

### 3.2 สร้างโปรเจกต์ใน Vercel

1. เข้า [vercel.com](https://vercel.com) > **Add New** > **Project**
2. เลือก repo ที่เพิ่ง push
3. Framework Preset ขึ้นว่า **Next.js** เอง — ไม่ต้องแก้อะไรในหน้านี้
4. **ยังไม่ต้องกด Deploy** ให้ไปใส่ค่าตัวแปรก่อน (ขั้นถัดไป)
   ถ้าเผลอ deploy ไปแล้วก็ไม่เป็นไร ใส่ค่าแล้ว Redeploy อีกรอบ

### 3.3 ใส่ค่าตัวแปร — ที่จำเป็นมีแค่ 2 ตัว

**Project Settings** > **Environment Variables**

| ชื่อ | ค่า | Environment |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL จากขั้น 2.5 | ติ๊กครบทั้ง 3 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key จากขั้น 2.5 | ติ๊กครบทั้ง 3 |

ติ๊กครบทั้ง Production, Preview และ Development
ไม่งั้นหน้า preview ของแต่ละ commit จะล็อกอินไม่ได้

### 3.4 Deploy แล้วตรวจ

1. **Deployments** > **Redeploy**
2. รอจนขึ้น Ready แล้วเปิดเว็บ
3. ล็อกอินด้วยผู้ใช้ที่สร้างไว้ในขั้น 2.4

> **สำคัญมาก:** ตัวแปรที่ขึ้นต้นด้วย `NEXT_PUBLIC_` ถูกฝังลงในไฟล์ตอน **build**
> ไม่ใช่ตอนรัน ใส่ค่าแล้วต้อง **Redeploy หนึ่งครั้ง** เสมอ ค่าใหม่ถึงจะมีผล
> นี่คือสาเหตุอันดับสองของการล็อกอินไม่ได้

## ตัวช่วยติดตั้ง — `npm run setup`

คู่มือบอกได้ว่า **ต้องทำอะไรบ้าง** แต่บอกไม่ได้ว่า **ตอนนี้คุณอยู่ตรงไหน**
คำสั่งนี้ตรวจของจริงให้ทีละข้อ แล้วสรุปเป็นรายการสิ่งที่ต้องทำต่อ

```
npm run setup
```

สั่งได้ทุกเมื่อ ทุกขั้น ไม่ต้องรอให้ติดตั้งเสร็จก่อน
และ**สั่งได้แม้ยังไม่เคย `npm install`** เพราะใช้แค่ของที่มากับ Node

### ตรวจอะไรบ้าง

| # | หมวด | ดูอะไร |
|---|---|---|
| 1 | ไฟล์ที่โปรเจกต์ต้องมี | `package.json` · `jsconfig.json` · `next.config.mjs` · `.gitignore` · `schema.sql` และ `.gitignore` กันไฟล์ลับจริงหรือไม่ |
| 2 | ไฟล์ค่าที่ตั้งไว้ (.env.local) | มีหรือยัง (ใส่ `--init` ให้สร้างจากไฟล์ตัวอย่างให้) |
| 3 | ค่าที่ขาดไม่ได้สองตัว | ตั้งแล้วหรือยัง · ยังเป็นค่าตัวอย่างอยู่ไหม · **เป็นกุญแจชนิดที่ถูกต้องไหม** |
| 4 | เชื่อมต่อ Supabase | ต่อได้ไหม · กุญแจใช้ได้ไหม · **ตารางครบ 44 ตารางหรือยัง** |
| 5 | ระบบล็อกอิน | เปิดให้สมัครสมาชิกเองค้างไว้ไหม · บังคับยืนยันอีเมลไหม · มีผู้ใช้แล้วกี่คน |
| 6 | ค่าเสริม (ไม่ใส่ก็ใช้งานได้) | ตั้งอะไรไว้แล้วบ้าง (ไม่ตั้งไม่ถือว่าผิด) |

หมวด 4 และ 5 **ยิงไปถาม Supabase จริง** ไม่ได้เดาจากไฟล์
รายชื่อตารางที่ใช้เทียบอ่านจาก `supabase/schema.sql` ตัวเดียวกับที่ใช้สร้างจริง
จึงไม่มีวันบอกจำนวนผิด

### อ่านผลอย่างไร

| คำ | แปลว่า |
|---|---|
| `ผ่าน` | ข้อนี้เรียบร้อย ไม่ต้องทำอะไร |
| `เตือน` | ใช้งานได้ แต่ควรแก้ เช่น เปิดให้สมัครสมาชิกเองค้างไว้ |
| `ไม่ผ่าน` | ต้องแก้ ไม่งั้นใช้งานไม่ได้ |
| `ข้าม` | ยังตรวจไม่ได้เพราะขั้นก่อนหน้ายังไม่เสร็จ หรือเป็นของเสริมที่ไม่ได้ตั้ง |

`ข้าม` **ไม่ใช่ความผิด** — แยกไว้เพราะถ้านับรวมเป็นความผิด
ความผิดข้อเดียวจะกลายเป็นห้าข้อ แล้วอ่านไม่ออกว่าต้นเหตุจริงคือข้อไหน

ท้ายผลลัพธ์จะสรุปว่าเหลือกี่เรื่อง พร้อมรายการที่ต้องทำเรียงตามลำดับ:

```
ยังไม่พร้อม — เหลืออีก 2 เรื่องที่ต้องแก้

ทำตามนี้ตามลำดับ:
  1. ใส่ Project URL จาก Supabase > Project Settings > API
  2. ใส่ anon public key จาก Supabase > Project Settings > API
```

ติดตั้งครบแล้วจะขึ้นว่า `พร้อมใช้งาน — ติดตั้งครบแล้ว` พร้อมบอกขั้นต่อไป

### สามเรื่องที่มันจับได้ แต่ตาคนมักมองข้าม

**1. เอา `service_role` key ไปใส่ช่อง anon**
มันอ่าน role จากตัวกุญแจเองแล้วฟ้องทันที
ข้อนี้พลาดแล้วใครเปิดเว็บก็ลบข้อมูลได้ทั้งระบบ และปกติ**ไม่มีอะไรเตือนเลย**
เพราะระบบยังทำงานได้ปกติทุกอย่าง

**2. ตารางขาดไปบางตัว**
บอกชื่อตารางที่ขาดมาให้เลย ไม่ใช่แค่บอกว่า "ไปรัน schema.sql"
เกิดบ่อยเวลาอัปเดตเป็นรุ่นที่มีตารางเพิ่มแล้วลืมรันซ้ำ

**3. เปิดให้สมัครสมาชิกเองค้างไว้**
เปิดไว้ตอนสร้างผู้ใช้ แล้วลืมปิด ใครก็สมัครเข้ามาเห็นข้อมูลทั้งระบบได้

### สิ่งที่มันตรวจไม่ได้

**ไม่ได้ตรวจค่าที่ตั้งไว้บน Vercel** — มันอ่านค่าจากเครื่องที่รันคำสั่ง
คือไฟล์ `.env.local` หรือค่าใน environment ของเครื่องนั้น
ถ้าจะดูว่า Vercel ตั้งครบไหม ต้องเปิดเว็บจริงแล้วดูว่ามีกล่องเหลืองขึ้นหรือไม่

**ไม่ได้ตรวจว่ารหัสผ่านของผู้ใช้ถูกหรือไม่** — ต้องลองล็อกอินเอง

**นับจำนวนผู้ใช้ได้เฉพาะเมื่อมี `SUPABASE_SERVICE_ROLE_KEY`** ซึ่งเป็นค่าไม่บังคับ
ไม่มีก็ข้ามไป แล้วไปดูเองที่ Authentication > Users

## ล็อกอินไม่ได้ — ไล่ตามลำดับนี้

**เริ่มจากสั่ง `npm run setup` ก่อน** ส่วนใหญ่มันบอกสาเหตุได้เลย
ถ้ามันขึ้นว่าพร้อมใช้งานแล้วแต่ยังล็อกอินไม่ได้ ค่อยไล่ตามตารางข้างล่าง
(ข้อที่พบบ่อยที่สุดคือ ตั้งค่าที่เครื่องครบ แต่ยังไม่ได้ตั้งที่ Vercel หรือตั้งแล้วไม่ได้ Redeploy)

ดูข้อความบนหน้าล็อกอินก่อน แล้วเทียบตาราง:

| ข้อความที่เห็น | แปลว่า | วิธีแก้ |
|---|---|---|
| กล่องเหลือง **"ยังไม่ได้ตั้งค่า Supabase"** พร้อมชื่อตัวแปร | ตัวแปรไม่ถึงหน้าเว็บ | ใส่ค่าที่ Vercel แล้ว **Redeploy** · ชื่อต้องสะกดตรงเป๊ะรวมทั้ง `NEXT_PUBLIC_` |
| **"อีเมลหรือรหัสผ่านไม่ถูกต้อง"** | ค่าที่ส่งไปไม่ตรงกับที่ Supabase มี | ตรวจว่าผู้ใช้มีจริงใน Authentication > Users · ตั้งรหัสใหม่ด้วย Reset password |
| **"อีเมลนี้ยังไม่ได้ยืนยัน"** | ลืมติ๊ก Auto Confirm User | Users > กดที่ผู้ใช้ > Confirm email |
| **"ไม่มีสิทธิ์เข้าถึง — ตรวจสอบ anon key"** | anon key ผิดหรือเป็นของโปรเจกต์อื่น | คัดลอก anon key ใหม่จาก Settings > API |
| **"พยายามเข้าสู่ระบบบ่อยเกินไป"** | Supabase จำกัดอัตราไว้ | รอสักครู่แล้วลองใหม่ |
| ล็อกอินผ่าน แต่หน้าจอว่างเปล่า / ขึ้นว่ายังไม่ได้ตั้งค่าตาราง | ยังไม่ได้รัน schema.sql หรือรันไม่จบ | กลับไปทำขั้น 2.2 แล้วดูตารางสรุปในขั้น 2.3 |
| บันทึกไม่ได้ ขึ้น **`42501 permission denied for sequence`** | สิทธิ์ sequence ยังไม่ได้ให้ | รัน `supabase/schema.sql` ทั้งไฟล์อีกครั้ง |

### ไล่หาสาเหตุเป็นขั้น ๆ

```
  ล็อกอินไม่ได้
        |
        v
  สั่ง  npm run setup
        |
        +-- ขึ้น "ยังไม่พร้อม"  -->  ทำตามรายการที่มันบอก แล้วลองใหม่   [จบ]
        |
        +-- ขึ้น "พร้อมใช้งาน"
                |
                v
        เปิดเว็บจริง มีกล่องเหลืองขึ้นไหม
                |
                +-- มี    -->  ยังไม่ได้ตั้งค่าที่ Vercel
                |              หรือตั้งแล้วแต่ยังไม่ได้ Redeploy        [จบ]
                |
                +-- ไม่มี
                        |
                        v
                กด F12 > แท็บ Network > ลองล็อกอิน > ดูคำขอ token
                        |
                        +-- ไม่มีคำขอเลย      -->  ตัวแปรไม่ถึงหน้าเว็บ
                        +-- ขึ้น 400          -->  อีเมลหรือรหัสผ่านไม่ตรง
                        +-- ขึ้น 401          -->  anon key ผิด
                        +-- Failed to fetch  -->  URL ผิด หรือโปรเจกต์ถูก pause
```

**ถ้าดูแล้วยังไม่รู้สาเหตุ** เปิด DevTools (กด F12) > แท็บ Network > ลองล็อกอินอีกครั้ง
แล้วดูคำขอที่ชื่อ `token?grant_type=password`

- ไม่มีคำขอนี้เลย → ตัวแปรไม่ถึงหน้าเว็บ (กลับไปข้อแรก)
- มีแต่ขึ้น 400 → อีเมลหรือรหัสผ่านไม่ตรง
- มีแต่ขึ้น 401 → anon key ผิด
- ขึ้น `Failed to fetch` → Project URL ผิด หรือโปรเจกต์ Supabase ถูกหยุด
  (โปรเจกต์ฟรีที่ไม่มีคนใช้เกิน 7 วันจะถูก pause — เข้า Dashboard กด Restore)

## คำสั่งที่ต้องใช้

### ติดตั้งและรันในเครื่อง

| คำสั่ง | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| `npm install` | ลงไลบรารีที่โปรเจกต์ต้องใช้ | ครั้งแรกที่ clone โค้ดมา |
| `npm run dev` | รันเว็บที่ localhost:3000 แก้ไฟล์แล้วรีเฟรชให้เอง | ตอนแก้โค้ดแล้วอยากเห็นผลทันที |
| `npm run build` | สร้างไฟล์ใช้งานจริง และจับ error ที่ตอนเขียนไม่ฟ้อง | ก่อน push ถ้าอยากมั่นใจว่า Vercel build ผ่าน |
| `npm run start` | รันไฟล์ที่ build แล้ว แบบเดียวกับบนเซิร์ฟเวอร์ | ทดสอบความเร็วจริง ต้อง build ก่อน |
| `npm run setup` | **ตรวจว่าติดตั้งถึงไหนแล้ว และบอกว่าต้องทำอะไรต่อ** | ตอนติดตั้ง และตอนระบบมีปัญหา |
| `npm run setup -- --init` | เหมือนข้างบน แต่สร้างไฟล์ `.env.local` จากไฟล์ตัวอย่างให้ด้วย | ครั้งแรกที่ตั้งค่าในเครื่อง |
| `npm run check` | **ตรวจความเรียบร้อยทั้งโปรเจกต์ 26 หมวด** | ทุกครั้งก่อน commit |

`npm run check` เป็นคำสั่งที่ใช้บ่อยที่สุด ทำงานโดยอ่านไฟล์ตรง ๆ
ไม่ต้องมี `node_modules` จึงรันได้แม้ยังไม่ได้ `npm install`

## ความปลอดภัย

ทำครบก่อนเปิดใช้จริง โดยเฉพาะข้อที่เขียนว่า **บังคับ**

### กุญแจและความลับ

**บังคับ — แยกกุญแจสองชนิดให้ออก**
`anon public` key เปิดเผยได้ ใส่ในหน้าเว็บได้ ความปลอดภัยมาจาก RLS
ส่วน `service_role` key ข้ามทุกสิทธิ์ **ห้ามออกจากฝั่งเซิร์ฟเวอร์**
ใส่ในหน้าเว็บเมื่อไร ใครเปิดเว็บก็อ่าน แก้ และลบข้อมูลทั้งระบบได้ทันที

**บังคับ — ชื่อตัวแปรลับห้ามขึ้นต้นด้วย `NEXT_PUBLIC_`**
Next.js ฝังเฉพาะตัวแปรที่ขึ้นต้นด้วยคำนี้ลงในไฟล์ที่เบราว์เซอร์โหลด
ตั้งชื่อผิดครั้งเดียวกุญแจหลุดทันทีและไม่มีอะไรเตือน — `npm run check` เฝ้าข้อนี้ให้

**บังคับ — `.env.local` ต้องไม่ขึ้น git**
หลุดขึ้นไปแล้วลบ commit ทีหลังก็ยังอยู่ในประวัติ

**เมื่อสงสัยว่ากุญแจหลุด** ไปที่ Supabase > Project Settings > API กด Reset
แล้วใส่ค่าใหม่ที่ Vercel และ Redeploy การลบไฟล์อย่างเดียวไม่ทำให้กุญแจเก่าใช้ไม่ได้

### บัญชีผู้ใช้

**บังคับ — หนึ่งคนหนึ่งบัญชี ห้ามใช้ร่วมกัน**
ทุกเอกสารบันทึกว่าใครเป็นคนทำ ใช้บัญชีร่วมกันแล้วตรวจสอบย้อนหลังไม่ได้เลย

**บังคับ — ปิดการสมัครสมาชิกเองเมื่อสร้างผู้ใช้ครบแล้ว**
Supabase > Authentication > Sign In / Providers > Email > ปิด `Allow new users to sign up`
เปิดค้างไว้ ใครก็สมัครเข้ามาเองได้แล้วเห็นข้อมูลทั้งระบบ

**บังคับ — ปิดใช้งานบัญชีคนที่ลาออกทันที**
ตั้งสถานะปิดใช้งานในทะเบียนผู้ใช้ และลบที่ Supabase > Authentication > Users

**แนะนำ — แอดมินต้องมีมากกว่าหนึ่งคน**
แอดมินคนเดียวลาออกหรือลืมรหัสผ่าน จะไม่มีใครตั้งสิทธิให้ใครได้อีกเลย

### สิทธิการใช้งาน — ข้อที่ต้องเข้าใจให้ตรงกัน

สิทธิรายหน้าจอคุมว่าใครเห็นเมนูไหนและกดแก้ไขได้ไหม
**เป็นการคุมลำดับงาน ไม่ใช่กำแพงกันข้อมูล**

คนที่ล็อกอินแล้วยังอ่านและเขียนตารางข้อมูลผ่าน API ได้ทุกตาราง
เพราะ policy ของตารางข้อมูลตั้งไว้ว่า "ผู้ที่ล็อกอินแล้วเข้าถึงได้"
(ยกเว้นสามตารางที่คุมสิทธิ ซึ่งเขียนได้เฉพาะแอดมิน)

**แปลว่า** ให้บัญชีระบบเฉพาะคนที่ไว้ใจให้เห็นข้อมูลทั้งหมดได้
ถ้าต้องกั้นถึงระดับข้อมูลจริง ๆ ต้องเขียน policy ตามบทบาทเพิ่มให้ทุกตาราง

### ฐานข้อมูล

**สองด่านของ Supabase ต้องผ่านทั้งคู่** — ด่านแรก `GRANT` ระดับตาราง ด่านสอง RLS policy
ไม่ผ่านด่านแรกได้ HTTP 403 ไม่ผ่านด่านสองอ่านได้ผลว่างหรือเขียนไม่ได้
อาการต่างกัน แก้คนละที่ แต่ทั้งคู่แก้ด้วยการรัน `schema.sql` ทั้งไฟล์

**เก็บรหัสผ่านฐานข้อมูลให้ปลอดภัย** รหัสที่ตั้งตอนสร้างโปรเจกต์ต่อฐานข้อมูลตรง ๆ ได้
ซึ่งข้ามทุกสิทธิ์เหมือน `service_role`

**รหัสผ่านการเชื่อมต่อฐานข้อมูลภายนอก** ค่าเริ่มต้นคือเก็บในเครื่องที่กรอกเท่านั้น
อย่าติ๊กให้เก็บขึ้นฐานข้อมูลเว้นแต่จำเป็น เพราะทุกคนที่ล็อกอินอ่านตารางนั้นได้
และค่าจะติดไปกับไฟล์สำรองข้อมูลด้วย

### ไฟล์สำรองข้อมูล

**ไฟล์สำรองคือข้อมูลจริงทั้งก้อน** มีทะเบียนลูกค้า ที่อยู่ เลขผู้เสียภาษี ราคาขาย
และเอกสารทุกใบ หลุดออกไปเท่ากับฐานข้อมูลหลุด ต่างกันแค่ไม่มีกุญแจติดไปด้วย
เก็บในที่ที่คุมสิทธิ์ได้ ไม่ส่งผ่านแชทหรืออีเมลโดยไม่ใส่รหัส

**ทดลองกู้คืนจริงอย่างน้อยหนึ่งครั้ง** ไฟล์สำรองที่กู้ไม่ได้ ไม่ใช่ไฟล์สำรอง
และจะรู้ตอนที่สายเกินไปเสมอ

### การเชื่อมต่อภายนอก

**ตัวรับข้อความจากไลน์ตรวจลายเซ็นทุกคำขอ** ด้วย HMAC-SHA256
ที่อยู่ webhook เป็น URL สาธารณะ ใครเดาถูกก็ยิงเข้ามาได้
ไม่ตรวจแล้วจะมีคำสั่งซื้อปลอมเต็มระบบ

**ข้อความจากไลน์ไม่กลายเป็นเอกสารเอง** ต้องมีคนกดตรวจและยืนยันเสมอ
ข้อมูลจากนอกระบบที่กลายเป็นเอกสารเองได้ คือช่องให้คนนอกสั่งงานระบบเรา

**จำกัดคนที่ใช้ผู้ช่วย AI ได้** ด้วย `CHAT_ALLOWED_EMAILS`
เพราะใช้โควตาที่เสียเงิน และคำถามอาจมีข้อมูลของกิจการปนไป

### การใช้งานประจำวัน

- **เปลี่ยนรหัสผ่านของตัวเองเป็นระยะ** ที่หน้าเปลี่ยนรหัสผ่านในโปรแกรม
- **ออกจากระบบเมื่อใช้เครื่องร่วมกัน** โดยเฉพาะเครื่องหน้าร้านและในคลัง
  ระบบจำการล็อกอินไว้ในเครื่อง ใครมานั่งต่อก็ใช้สิทธิของคนก่อนหน้าได้ทันที
- เว็บใช้ HTTPS อยู่แล้วจาก Vercel ข้อมูลระหว่างทางปลอดภัย
  แต่เครื่องที่ติดมัลแวร์หรือมีคนดูจอ ยังเป็นความเสี่ยงที่ HTTPS ช่วยไม่ได้

| ชื่อ | จำเป็น | หมายเหตุ |
|---|---|---|

**ไม่ใส่ก็ใช้เมนูงานผ่านไลน์ได้ครบทุกอย่าง** ผ่านการนำเข้าไฟล์แชทหรือวางข้อความ
ค่าสองตัวนี้ทำให้ข้อความไหลเข้ามาเองตอนลูกค้าพิมพ์เท่านั้น
ขั้นตอนทั้งหมดดูที่หน้าจอ **ตั้งค่าการเชื่อมต่อไลน์** ในโปรแกรม ซึ่งบอกด้วยว่าตั้งครบหรือยัง

> ทั้งสองตัว**ห้ามมี `NEXT_PUBLIC_` นำหน้า** ถ้าใส่ ค่าจะถูกฝังลงไปในหน้าเว็บ
> ใครเปิด DevTools ก็คัดลอกไปใช้ได้ โดยเฉพาะ service_role key ที่ข้ามทุกสิทธิ์

## สรุปค่าที่จำเป็นทั้งหมด

ขั้นต่ำที่ทำให้ระบบใช้งานได้ **มีแค่สองตัว**

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
```

บวกกับสามอย่างที่ไม่ใช่ตัวแปร แต่ขาดไม่ได้:

1. รัน `supabase/schema.sql` ทั้งไฟล์ และตารางสรุปต้องขึ้น `ผ่าน` ทุกแถว
2. สร้างผู้ใช้พร้อม **ติ๊ก Auto Confirm User**
3. **Redeploy หนึ่งครั้ง** หลังใส่ค่าตัวแปร

## สำรองข้อมูล

เมนู **สำรองข้อมูล** ดาวน์โหลดได้ทั้งระบบเป็นไฟล์เดียว และกู้คืนกลับได้
ควรทำก่อนอัปเดตรุ่นใหญ่ทุกครั้ง

ไฟล์สำรองมีข้อมูลจริงทั้งหมดรวมถึงข้อมูลลูกค้า เก็บให้ปลอดภัยเท่ากับฐานข้อมูล
แต่**ไม่มีกุญแจที่อยู่ใน Environment Variables** เพราะค่าพวกนั้นไม่ได้เก็บในฐานข้อมูล
