## ขั้นที่ 1 — วางโครงโฟลเดอร์

### ทางที่ 1: คัดลอกจากโปรเจกต์เดิม (แนะนำ)

```
git clone <ที่อยู่ repo เดิม> ชื่อโปรเจกต์ใหม่
cd ชื่อโปรเจกต์ใหม่
```

### ทางที่ 2: สร้างใหม่ทั้งหมด

โครงที่ต้องมี — ชื่อโฟลเดอร์ต้องตรงตามนี้ เพราะ Next.js หาไฟล์จากชื่อ:

```
ชื่อโปรเจกต์/
├─ app/                  หน้าเว็บและ API (Next.js App Router)
│  ├─ layout.js          โครงร่างหน้าเว็บ
│  ├─ page.js            หน้าแรก
│  ├─ globals.css        สไตล์ทั้งระบบ (ไฟล์เดียว)
│  └─ api/               Route Handler ที่รันฝั่งเซิร์ฟเวอร์
├─ components/           ส่วนประกอบหน้าจอ
│  └─ views/             หนึ่งไฟล์ต่อหนึ่งหน้าจอ
├─ lib/                  ตรรกะล้วน ไม่มี JSX — ทดสอบใน Node ได้ตรง ๆ
├─ public/               ไฟล์ที่เสิร์ฟตรง (โลโก้ ไอคอน manifest)
├─ supabase/
│  └─ schema.sql         สร้างฐานข้อมูลทั้งหมดจากไฟล์เดียว
├─ tools/                สคริปต์ช่วยงาน (ตัวตรวจ ตัวสร้างเอกสาร)
├─ Docs/                 เอกสารโครงการ
├─ package.json
├─ next.config.mjs
├─ jsconfig.json         ทำให้ import แบบ @/lib/... ใช้ได้
└─ .env.local            ค่าลับ — ห้ามขึ้น git (อยู่ใน .gitignore แล้ว)
```

**สามโฟลเดอร์ที่ห้ามสลับกัน**

- `lib/` ต้องไม่มี JSX เลย เพราะไฟล์ในนี้ถูกทดสอบด้วย Node ตรง ๆ โดยไม่ผ่าน build
- `components/` เป็นหน้าจอ ห้ามใส่ตรรกะการคำนวณ เพราะทดสอบไม่ได้
- `app/api/` รันฝั่งเซิร์ฟเวอร์เท่านั้น กุญแจลับอยู่ที่นี่ได้ที่เดียว

### ไฟล์ตั้งค่าที่ต้องมี

`package.json` — ส่วนที่ขาดไม่ได้:

```json
{
  "name": "ofau",
  "private": true,
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "check": "node tools/check.mjs"
  },
  "dependencies": {
    "next": "^15.5.0",
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  },
  "engines": { "node": ">=18.18.0" }
}
```

`jsconfig.json` — ถ้าไม่มีไฟล์นี้ `import ... from "@/lib/db"` จะพังทุกไฟล์:

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./*"] }
  }
}
```

`.gitignore` — ต้องมีสามบรรทัดนี้เป็นอย่างน้อย:

```
node_modules
.next
.env*.local
```

> `.env.local` หลุดขึ้น git เมื่อไร กุญแจในนั้นถือว่ารั่วทันที
> ต่อให้ลบ commit ทีหลังก็ยังอยู่ในประวัติ ต้องไปสร้างกุญแจใหม่ที่ Supabase

## ขั้นที่ 2 — สร้างฐานข้อมูลใน Supabase

### 2.1 สร้างโปรเจกต์

1. เข้า [supabase.com](https://supabase.com) > **New project**
2. ตั้งชื่อ และ **ตั้งรหัสผ่านฐานข้อมูล** (เก็บไว้ ใช้ตอนต่อฐานข้อมูลตรง ๆ)
3. เลือก Region ให้ใกล้ผู้ใช้ — **Southeast Asia (Singapore)** สำหรับผู้ใช้ในไทย
   เลือกผิดภูมิภาคแล้วย้ายทีหลังไม่ได้ ต้องสร้างโปรเจกต์ใหม่
4. รอประมาณ 2 นาทีจนสถานะขึ้นว่าพร้อม

### 2.2 รัน schema.sql — ขั้นตอนเดียวจบ

1. เมนูซ้าย > **SQL Editor** > **New query**
2. เปิดไฟล์ `supabase/schema.sql` **คัดลอกทั้งไฟล์** วางลงไป
3. กด **Run**

ไฟล์เดียวนี้ทำให้ครบทุกอย่าง:

| ทำอะไร | ทำไมต้องมี |
|---|---|
| สร้างตารางทั้ง 44 ตาราง | ข้ามตารางที่มีอยู่แล้ว ไม่แตะข้อมูลเดิม |
| สร้างฟังก์ชันบันทึกเอกสารแบบ atomic | ขายหนึ่งครั้งเขียน 3 ตาราง สำเร็จหมดหรือไม่สำเร็จเลย |
| เพิ่มเลขลำดับแถว (row_order) ทุกตาราง | ใช้เรียงและอ้างอิง เพราะ id เป็นข้อความสุ่ม |
| GRANT สิทธิ์ระดับตารางให้ role authenticated | ไม่ผ่านด่านนี้จะได้ HTTP 403 ทุกคำขอ |
| **GRANT สิทธิ์ sequence** | ขาดแล้วบันทึกไม่ได้เลยทุกตาราง (ดูหัวข้อแก้ปัญหา) |
| เปิด RLS และสร้าง policy ครบทุกตาราง | กันไม่ให้คนที่ไม่ได้ล็อกอินอ่านหรือเขียน |
| ตั้งทะเบียนผู้ใช้และสิทธิรายคน | คนที่สมัครก่อนสุดได้เป็นแอดมินอัตโนมัติ |

**รันซ้ำกี่ครั้งก็ได้ ปลอดภัย ไม่ลบข้อมูลเดิม** — และต้องรันซ้ำทุกครั้งที่อัปเดตโปรแกรมเป็นรุ่นที่มีตารางใหม่

### 2.3 ตรวจผลลัพธ์ — ข้อนี้ห้ามข้าม

ท้ายผลลัพธ์จะมีตารางสรุป **ทุกแถวต้องขึ้นว่า `ผ่าน`**

ถ้าเจอแถวที่ไม่ผ่าน อ่านข้อความแล้วแก้ตามนี้:

| ข้อความ | สาเหตุและวิธีแก้ |
|---|---|
| ไม่ผ่าน — ไม่มีตาราง | รันไฟล์ไม่ครบ ให้คัดลอกทั้งไฟล์แล้วรันใหม่ |
| ไม่ผ่าน — GRANT ไม่ครบ | รันไฟล์ไม่จบ ดูว่ามี error สีแดงกลางทางหรือไม่ |
| ไม่ผ่าน — ไม่มี RLS policy | เหมือนข้างบน |
| ไม่ผ่าน — sequence ยังไม่ได้ GRANT | รันไฟล์ใหม่ทั้งไฟล์ ต้องรันส่วนท้ายให้ถึง |

### 2.4 สร้างผู้ใช้คนแรก

ระบบนี้**ไม่มีหน้าสมัครสมาชิก** โดยตั้งใจ ผู้ใช้ถูกสร้างจาก Dashboard เท่านั้น

1. เมนูซ้าย > **Authentication** > **Users** > **Add user**
2. กรอกอีเมลและรหัสผ่าน
3. **ติ๊ก `Auto Confirm User`** ← ข้อนี้สำคัญที่สุด

> ไม่ติ๊กข้อนี้ จะล็อกอินไม่ได้เลย และระบบจะขึ้นว่า
> *"อีเมลนี้ยังไม่ได้ยืนยัน"* ซึ่งเป็นสาเหตุที่พบบ่อยที่สุดของการล็อกอินไม่ได้
> แก้ย้อนหลังได้ที่ Users > กดที่ผู้ใช้ > Confirm email

คนที่ถูกสร้างก่อนสุดจะได้เป็น **แอดมิน** อัตโนมัติ (ตั้งสิทธิให้คนอื่นได้)

### 2.5 เอาค่าสองตัวมาใช้ต่อ

**Project Settings** > **API** แล้วคัดลอกสองค่านี้:

| ช่องใน Supabase | เอาไปใส่ชื่อ |
|---|---|
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` |
| Project API keys > **anon** `public` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |

> **อย่าหยิบ `service_role` มาใส่เป็น anon key เด็ดขาด**
> กุญแจนั้นข้ามทุกสิทธิ์ ฝังไว้ในหน้าเว็บเมื่อไร ใครเปิดหน้าเว็บก็ลบข้อมูลทั้งระบบได้
> anon key เปิดเผยได้ตามปกติ ความปลอดภัยมาจาก RLS policy ที่ schema.sql ตั้งไว้แล้ว

## ขั้นที่ 3 — ตั้งค่าและ deploy บน Vercel

### 3.1 เอาโค้ดขึ้น GitHub

```
git init
git add .
git commit -m "เริ่มโครงการ"
git branch -M main
git remote add origin <ที่อยู่ repo ของคุณ>
git push -u origin main
```

### 3.2 สร้างโปรเจกต์ใน Vercel

1. เข้า [vercel.com](https://vercel.com) > **Add New** > **Project**
2. เลือก repo ที่เพิ่ง push
3. Framework Preset ขึ้นว่า **Next.js** เอง — ไม่ต้องแก้อะไรในหน้านี้
4. **ยังไม่ต้องกด Deploy** ให้ไปใส่ค่าตัวแปรก่อน (ขั้นถัดไป)
   ถ้าเผลอ deploy ไปแล้วก็ไม่เป็นไร ใส่ค่าแล้ว Redeploy อีกรอบ

### 3.3 ใส่ค่าตัวแปร — ที่จำเป็นมีแค่ 2 ตัว

**Project Settings** > **Environment Variables**

| ชื่อ | ค่า | Environment |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL จากขั้น 2.5 | ติ๊กครบทั้ง 3 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key จากขั้น 2.5 | ติ๊กครบทั้ง 3 |

ติ๊กครบทั้ง Production, Preview และ Development
ไม่งั้นหน้า preview ของแต่ละ commit จะล็อกอินไม่ได้

### 3.4 Deploy แล้วตรวจ

1. **Deployments** > **Redeploy**
2. รอจนขึ้น Ready แล้วเปิดเว็บ
3. ล็อกอินด้วยผู้ใช้ที่สร้างไว้ในขั้น 2.4

> **สำคัญมาก:** ตัวแปรที่ขึ้นต้นด้วย `NEXT_PUBLIC_` ถูกฝังลงในไฟล์ตอน **build**
> ไม่ใช่ตอนรัน ใส่ค่าแล้วต้อง **Redeploy หนึ่งครั้ง** เสมอ ค่าใหม่ถึงจะมีผล
> นี่คือสาเหตุอันดับสองของการล็อกอินไม่ได้

## ล็อกอินไม่ได้ — ไล่ตามลำดับนี้

ดูข้อความบนหน้าล็อกอินก่อน แล้วเทียบตาราง:

| ข้อความที่เห็น | แปลว่า | วิธีแก้ |
|---|---|---|
| กล่องเหลือง **"ยังไม่ได้ตั้งค่า Supabase"** พร้อมชื่อตัวแปร | ตัวแปรไม่ถึงหน้าเว็บ | ใส่ค่าที่ Vercel แล้ว **Redeploy** · ชื่อต้องสะกดตรงเป๊ะรวมทั้ง `NEXT_PUBLIC_` |
| **"อีเมลหรือรหัสผ่านไม่ถูกต้อง"** | ค่าที่ส่งไปไม่ตรงกับที่ Supabase มี | ตรวจว่าผู้ใช้มีจริงใน Authentication > Users · ตั้งรหัสใหม่ด้วย Reset password |
| **"อีเมลนี้ยังไม่ได้ยืนยัน"** | ลืมติ๊ก Auto Confirm User | Users > กดที่ผู้ใช้ > Confirm email |
| **"ไม่มีสิทธิ์เข้าถึง — ตรวจสอบ anon key"** | anon key ผิดหรือเป็นของโปรเจกต์อื่น | คัดลอก anon key ใหม่จาก Settings > API |
| **"พยายามเข้าสู่ระบบบ่อยเกินไป"** | Supabase จำกัดอัตราไว้ | รอสักครู่แล้วลองใหม่ |
| ล็อกอินผ่าน แต่หน้าจอว่างเปล่า / ขึ้นว่ายังไม่ได้ตั้งค่าตาราง | ยังไม่ได้รัน schema.sql หรือรันไม่จบ | กลับไปทำขั้น 2.2 แล้วดูตารางสรุปในขั้น 2.3 |
| บันทึกไม่ได้ ขึ้น **`42501 permission denied for sequence`** | สิทธิ์ sequence ยังไม่ได้ให้ | รัน `supabase/schema.sql` ทั้งไฟล์อีกครั้ง |

**ถ้าดูแล้วยังไม่รู้สาเหตุ** เปิด DevTools (กด F12) > แท็บ Network > ลองล็อกอินอีกครั้ง
แล้วดูคำขอที่ชื่อ `token?grant_type=password`

- ไม่มีคำขอนี้เลย → ตัวแปรไม่ถึงหน้าเว็บ (กลับไปข้อแรก)
- มีแต่ขึ้น 400 → อีเมลหรือรหัสผ่านไม่ตรง
- มีแต่ขึ้น 401 → anon key ผิด
- ขึ้น `Failed to fetch` → Project URL ผิด หรือโปรเจกต์ Supabase ถูกหยุด
  (โปรเจกต์ฟรีที่ไม่มีคนใช้เกิน 7 วันจะถูก pause — เข้า Dashboard กด Restore)

## รันในเครื่องตัวเอง (ไม่บังคับ)

```
npm install
cp .env.local.example .env.local     # แล้วแก้ค่าสองตัวแรกให้เป็นค่าจริง
npm run dev
```

เปิด <http://localhost:3000>

`.env.local` ใช้ค่าเดียวกับที่ใส่ใน Vercel และ**ต้องไม่ขึ้น git**

### ตรวจความเรียบร้อยก่อน push

```
npm run check
```

ตรวจ 26 หมวด ทำงานโดยอ่านไฟล์ตรง ๆ ไม่ต้องมี `node_modules`
จับบั๊กที่ไม่มีใครฟ้องตอนแก้โค้ดแต่จอขาวตอนเปิดใช้จริง เช่น ส่ง prop
ที่ไม่มีตัวแปรอยู่จริง หรือหัวตารางมีคอลัมน์ไม่เท่าแถวข้อมูล

| `GEMINI_MODEL` | ไม่ | ไม่ใส่จะใช้ค่าเริ่มต้น |
| `CHAT_ALLOWED_EMAILS` | ไม่ | จำกัดว่าใครใช้ได้ คั่นด้วยจุลภาค เว้นว่าง = ทุกคนที่ล็อกอิน |

ไม่ใส่ก็ได้ ปุ่มผู้ช่วยยังอยู่แต่จะบอกว่ายังไม่ได้ตั้งค่า

### รับข้อความจากไลน์อัตโนมัติ

| ชื่อ | จำเป็น | หมายเหตุ |
|---|---|---|
| `LINE_CHANNEL_SECRET` | ถ้าอยากใช้ | จาก developers.line.biz > Basic settings |
| `SUPABASE_SERVICE_ROLE_KEY` | ถ้าอยากใช้ | จาก Supabase > Settings > API |

**ไม่ใส่ก็ใช้เมนูงานผ่านไลน์ได้ครบทุกอย่าง** ผ่านการนำเข้าไฟล์แชทหรือวางข้อความ
ค่าสองตัวนี้ทำให้ข้อความไหลเข้ามาเองตอนลูกค้าพิมพ์เท่านั้น
ขั้นตอนทั้งหมดดูที่หน้าจอ **ตั้งค่าการเชื่อมต่อไลน์** ในโปรแกรม ซึ่งบอกด้วยว่าตั้งครบหรือยัง

> ทั้งสองตัว**ห้ามมี `NEXT_PUBLIC_` นำหน้า** ถ้าใส่ ค่าจะถูกฝังลงไปในหน้าเว็บ
> ใครเปิด DevTools ก็คัดลอกไปใช้ได้ โดยเฉพาะ service_role key ที่ข้ามทุกสิทธิ์

### ที่อยู่เว็บสำหรับการ์ดพรีวิว

`NEXT_PUBLIC_SITE_URL` — ใส่เมื่อใช้โดเมนของตัวเอง
ไม่ใส่ ระบบจะหยิบโดเมนของ Vercel มาให้เอง

## สรุปค่าที่จำเป็นทั้งหมด

ขั้นต่ำที่ทำให้ระบบใช้งานได้ **มีแค่สองตัว**

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
```

บวกกับสามอย่างที่ไม่ใช่ตัวแปร แต่ขาดไม่ได้:

1. รัน `supabase/schema.sql` ทั้งไฟล์ และตารางสรุปต้องขึ้น `ผ่าน` ทุกแถว
2. สร้างผู้ใช้พร้อม **ติ๊ก Auto Confirm User**
3. **Redeploy หนึ่งครั้ง** หลังใส่ค่าตัวแปร

## อัปเดตโปรแกรมเป็นรุ่นใหม่

```
git pull
```

Vercel deploy ให้เองเมื่อ push ขึ้น main

**ถ้ารุ่นใหม่มีตารางเพิ่ม** ต้องรัน `supabase/schema.sql` ทั้งไฟล์อีกครั้ง
ไฟล์นี้ข้ามของที่มีอยู่แล้วและไม่ลบข้อมูลเดิม รันซ้ำได้เสมอ
หน้าจอที่ยังไม่มีตารางจะขึ้นข้อความบอกเองว่าต้องรันอะไร ไม่ได้ขึ้นจอขาว

## สำรองข้อมูล

เมนู **สำรองข้อมูล** ดาวน์โหลดได้ทั้งระบบเป็นไฟล์เดียว และกู้คืนกลับได้
ควรทำก่อนอัปเดตรุ่นใหญ่ทุกครั้ง

ไฟล์สำรองมีข้อมูลจริงทั้งหมดรวมถึงข้อมูลลูกค้า เก็บให้ปลอดภัยเท่ากับฐานข้อมูล
แต่**ไม่มีกุญแจที่อยู่ใน Environment Variables** เพราะค่าพวกนั้นไม่ได้เก็บในฐานข้อมูล
