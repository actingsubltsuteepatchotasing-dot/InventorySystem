# Overview
จัดทำโปรแกรมควบคุมสินค้าคงคลัง
โทนสีเขียวของการยางแห่งประเทศไทย
มีหน้าจอ รับสินค้า เบิกสินค้า โอนสินค้า การปรับปรุงสินค้า
มีรายงานสรุปแต่ละหน้าจอที่ทำรายการ
มีหน้าจอกำหนดรายละเอียดสินค้า ใส่รูป ใส่บาร์โค๊ดได้
มีหน้าจอแสดงสินค้าที่อยู่ในแต่ละจังหวัด อ้างอิงแผนที่จาก google map
มีการพิมพ์รายงานการตรวจนับสินค้า
มีกราฟสรุปปริมาณขึ้นลงคงเหลือ

# ตั้งค่าก่อนใช้งาน  (สำคัญ — ทำ 3 ขั้นนี้ก่อน ไม่งั้น login ไม่ได้)

ขั้นที่ 1 — สร้างตารางใน Supabase
  Supabase Dashboard > SQL Editor > New query
  วางเนื้อหาไฟล์ supabase/schema.sql ทั้งไฟล์ แล้วกด Run
  (รันซ้ำได้ปลอดภัย ใช้ if not exists)

ขั้นที่ 2 — สร้างผู้ใช้
  Authentication > Users > Add user
    Email    : อีเมลที่ต้องการ (เช่น admin@raot.local)
    Password : ตั้งรหัสที่ปลอดภัย
    ☑ Auto Confirm User   <- ต้องติ๊ก ไม่งั้นจะติด "Email not confirmed"

ขั้นที่ 3 — ใส่ค่า environment
  หาค่าที่ Project Settings > API
    Project URL              -> NEXT_PUBLIC_SUPABASE_URL
    Project API keys > anon  -> NEXT_PUBLIC_SUPABASE_ANON_KEY

  ตอน deploy : Vercel > Project Settings > Environment Variables
               ใส่ทั้งสองค่า แล้ว Redeploy หนึ่งครั้ง
               (ตัวแปร NEXT_PUBLIC_ ถูกฝังตอน build จึงต้อง build ใหม่)
  ตอนรันในเครื่อง : คัดลอก .env.local.example เป็น .env.local แล้วใส่ค่า

  หมายเหตุ: anon key เป็น public key เปิดเผยได้ ความปลอดภัยมาจาก RLS policy
            ห้ามใช้ service_role key ในฝั่ง client เด็ดขาด

เมื่อเข้าระบบครั้งแรกและฐานข้อมูลยังว่าง ระบบจะสร้างข้อมูลตัวอย่างให้อัตโนมัติ


# โครงสร้างฐานข้อมูล (supabase/schema.sql)

warehouses   id, code, name, province, lat, lng
products     id, code(unique), name, unit, cat, price, min_qty, barcode, img, note
txns         id, type, doc_no, date, product_id -> products(cascade),
             qty, wh_id -> warehouses, wh_to -> warehouses,
             note, ref, user_name, ts

ข้อบังคับที่ตั้งไว้ในฐานข้อมูล (ไม่ใช่แค่ฝั่งหน้าจอ):
  - type ต้องเป็น RECEIVE / ISSUE / TRANSFER / ADJUST เท่านั้น
  - รายการ TRANSFER ต้องมี wh_to และ wh_to <> wh_id  (กันโอนเข้าคลังตัวเอง)
  - ลบสินค้า -> รายการเคลื่อนไหวที่อ้างถึงถูกลบตาม (on delete cascade)
  - ลบคลังที่ยังมีรายการอ้างอยู่ไม่ได้ (on delete restrict)

การเข้าถึงตารางต้องผ่าน 2 ด่าน (สำคัญ — เคยพลาดตรงนี้)
  ด่าน 1  GRANT ระดับตาราง ให้ role authenticated
          ไม่ผ่าน -> HTTP 403 / SQLSTATE 42501 "permission denied for table"
  ด่าน 2  RLS policy
          ไม่ผ่าน -> อ่านได้ผลว่าง หรือเขียนไม่ได้ ("new row violates ...")

RLS: เปิดทั้ง 3 ตาราง อนุญาตเฉพาะ role = authenticated
     anon key เพียงอย่างเดียวอ่าน/เขียนไม่ได้ ต้อง login ก่อนเสมอ

หมายเหตุชื่อคอลัมน์: ใช้ min_qty และ user_name แทน min / user
เพราะ user เป็นคำสงวนของ SQL — การแปลงชื่อทำที่ lib/api.js

# วิธีทำงานของข้อมูล

โหลด : เข้าระบบสำเร็จ -> InventoryProvider ดึง products/warehouses/txns ทั้งหมด
       มาเก็บในหน่วยความจำครั้งเดียว (แบ่งหน้าครั้งละ 1000 แถว)
       ทุกหน้าจอจึงเร็วเพราะคำนวณจากหน่วยความจำ ไม่ยิง query ซ้ำ

เขียน : เขียนขึ้น Supabase ก่อนเสมอ ถ้าสำเร็จจึงอัปเดตหน่วยความจำ
       ถ้าเขียนพลาด สถานะบนหน้าจอจะไม่เปลี่ยน และขึ้นข้อความแจ้งเตือน
       (ไม่ใช้ optimistic update เพื่อกันหน้าจอกับฐานข้อมูลไม่ตรงกัน)

เลขที่เอกสาร : คำนวณจากเลขสูงสุดที่มีอยู่จริงใน txns ไม่ใช้ตัวนับแยก
              เพราะฐานข้อมูลใช้ร่วมกันหลายเครื่อง ตัวนับฝั่ง client จะไม่ตรงกัน

# ข้อมูลตัวอย่าง (สร้างอัตโนมัติเมื่อฐานข้อมูลว่าง — แก้ไข/ลบได้ทั้งหมด)
- สินค้า 12 รายการ: น้ำยางข้น 60%, RSS3, STR 20, ยางเครพ, ถุงมือยาง, หมอนยางพารา,
  แผ่นยางปูพื้น, กรดฟอร์มิก, ปุ๋ย 20-8-20, ถ้วยรองน้ำยาง, มีดกรีดยาง, ถังเก็บน้ำยาง
- คลัง 10 แห่ง 10 จังหวัด: กรุงเทพฯ, สุราษฎร์ธานี, สงขลา, นครศรีธรรมราช, ตรัง,
  ยะลา, ระยอง, บึงกาฬ, อุบลราชธานี, เชียงราย (มีพิกัด lat/lng สำหรับ Google Map)
- รายการเคลื่อนไหว 431 รายการ ย้อนหลัง 8 เดือน (ใช้ตัวสุ่มแบบ seed คงที่)
- ปุ่ม "ข้อมูล" มุมขวาบน = ส่งออก/นำเข้าไฟล์สำรอง, โหลดใหม่, ล้างและสร้างใหม่
  ระวัง: นำเข้าและรีเซ็ตมีผลกับ Supabase จึงกระทบผู้ใช้ทุกคน ไม่ใช่แค่เครื่องตัวเอง


# ผลการทดสอบ (2026-08-28)

ก. ตรวจโครงสร้างโค้ด 33 ไฟล์ — ผ่านทั้งหมด
   - import ทุกเส้นทางมีไฟล์จริง และชื่อ named import มี export จริง
   - วงเล็บ/ปีกกาสมดุลทุกไฟล์
   - ไฟล์ที่ใช้ React hook ประกาศ "use client" ครบ
   - ไม่มีการเรียก localStorage/window/document ที่ระดับ module (กัน SSR พัง)
   - แท็ก void ใน JSX ปิดตัวเองครบ

ข. ทดสอบตรรกะด้วย Node 57 ข้อ — ผ่านทั้งหมด
   บาร์โค๊ด Code 128-B    ตาราง 107 รายการ, จำนวนแท่งตรงสเปก, กรองอักขระนอก ASCII
   ข้อมูลตั้งต้น          จำนวน/ความครบถ้วน/การอ้างอิง/เรียงเวลา/สร้างซ้ำได้ผลเดิม
   การคำนวณยอด           ผลรวมรายสินค้า = รายคลัง (186,457)
   ตรรกะการโอน            ต้นทางลด/ปลายทางเพิ่ม/คลังอื่นไม่กระทบ,
                          ยอดรวมทั้งองค์กรไม่เปลี่ยน
   เลขที่เอกสาร           = เลขสูงสุดที่มีอยู่ + 1, ขยับเองหลังบันทึก,
                          เดือนใหม่เริ่ม 0001, ไม่ซ้ำ
   ความสอดคล้องกับ schema  ชื่อคอลัมน์ใน api.js ตรงกับ schema.sql ทุกตัว,
                          ไม่ใช้คำสงวน user, RLS เปิดครบ 3 policy,
                          จำกัดเฉพาะ authenticated, ไม่พาดพิง service_role

ค. ยังไม่ได้รัน `next build` และยังไม่ได้ทดสอบกับ Supabase จริง
   - build: ต้อง npm install ก่อน ซึ่งขัดข้อกำหนด "ไม่ต้องติดตั้งอะไร"
     Vercel จะ build ให้เองตอน deploy
   - Supabase: ยังไม่มี URL/anon key ของโปรเจกต์จริง จึงยังไม่ได้ยิง request จริง
     เส้นทางที่ยังไม่ได้พิสูจน์: login, โหลดข้อมูล, บันทึกเอกสาร, refresh token


# ข้อจำกัดที่ควรทราบ
- เลขที่เอกสารคำนวณฝั่ง client ถ้าผู้ใช้ 2 คนกดบันทึกพร้อมกันในเดือนเดียวกัน
  อาจได้เลขซ้ำได้ (ฐานข้อมูลไม่ได้บังคับ unique ไว้)
  ถ้าต้องการกันจริงจัง ให้เพิ่ม unique index บน doc_no หรือย้ายไปออกเลขด้วย
  Postgres sequence / function ฝั่งเซิร์ฟเวอร์
- ข้อมูลถูกโหลดมาทั้งหมดตอนเข้าระบบ เหมาะกับข้อมูลระดับหลักหมื่นแถว
  ถ้าโตกว่านั้นควรเปลี่ยนไปโหลดเฉพาะช่วงที่ดูอยู่
- รูปสินค้าเก็บเป็น data URL ในคอลัมน์ text ถ้ามีรูปเยอะควรย้ายไปใช้ Supabase Storage
- ผู้ใช้ที่ล็อกอินแล้วทุกคนมีสิทธิ์เท่ากันทั้งหมด (อ่าน/เขียน/ลบได้ทุกอย่าง)
  ยังไม่มีระบบแบ่งบทบาท เช่น ผู้ดูแล / เจ้าหน้าที่คลัง / ผู้อ่านอย่างเดียว
- แผนที่ต้องเชื่อมต่ออินเทอร์เน็ต (Google Maps Embed)
- ระบบต้องออนไลน์ตลอด ใช้งาน offline ไม่ได้แล้ว (ต่างจากรุ่น localStorage เดิม)


# ปัญหาที่เคยเจอและวิธีแก้

อาการ: login ผ่าน แต่ขึ้น "เชื่อมต่อฐานข้อมูลไม่สำเร็จ / ไม่มีสิทธิ์เข้าถึงข้อมูล"
สาเหตุ: schema.sql รุ่นแรกตั้ง RLS policy อย่างเดียว ลืม GRANT ระดับตาราง
วิธีแก้: รัน supabase/fix-permissions.sql ใน SQL Editor แล้วดูผล query 3 ชุดท้ายไฟล์
        - rls_enabled ต้องเป็น true ครบ 3 แถว
        - ต้องมี policy 3 แถว roles = {authenticated}
        - authenticated ต้องมีสิทธิ์ SELECT/INSERT/UPDATE/DELETE ครบทั้ง 3 ตาราง

อาการ: "Email not confirmed"
วิธีแก้: Authentication > Users > แก้ผู้ใช้นั้น แล้วยืนยันอีเมล
        หรือสร้างใหม่โดยติ๊ก Auto Confirm User
